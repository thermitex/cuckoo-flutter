Moodle
Connectivity

Cuckoo is designed from bottom-up to be compliant with Moodle's mobile-specific APIs, which are the same set of standards followed by the official Moodle App. Cuckoo uses a set of encrypted tokens requested from Moodle service to identify yourself in its communications with Moodle to fetch events, view courses, and so on, and therefore your sensitive credentials such as your SSO password or Cookie information will no longer be required to be saved on device. To learn more about Cuckoo's authentication procedure, check the source code here.

Compared with the scraping strategy adopted in Cuckoo 1.0, the new communication approach enables Cuckoo to fetch information much faster, create sessions that do not easily expire, and also extend the functionality to send actions back to Moodle with write access granted (e.g., sync completion status). When the institution updates the Moodle website (yes they do it many times during the summer break), the features can still remain available without extra updates. The communications are encrypted and safely transported via TLS as well.
